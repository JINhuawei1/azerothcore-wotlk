# 幻境倍率公式化扩展 — 设计文档

- 日期:2026-07-18
- 涉及模块:`mod-item-identification-system`(物品鉴定)、`mod-huanjinxitong`(幻境系统)、`int256字段升级`(SQL)
- 目标分支:`feature/large-changes-20260425`

## 一、问题

玩家希望把幻境等级开放到 **1 亿甚至 100 亿**,并且高等级要对应超大的生物属性 / 装备鉴定属性倍率。
但现状是"**一级一行数据**":

- `_物品鉴定_模板`:当前用 `_物品鉴定_模板_20档动态词缀.sql` 预生成 **5000 等级档 × 20 稀有度 = 10 万行**。等级到 1 亿后,这种"组号=等级"的物化方式需要 20 亿行,不现实。
- `_幻境生物属性`:每个幻境等级配一行倍率。1 亿等级 = 1 亿行。

要 1 亿/100 亿行数据显然不可行。

## 二、核心思路(用户提出,已确认)

**不物化,改公式化。数据库只存"基础模板 + 每级增量系数",运行时按公式即时算出任意等级的数值。**

三条:

1. **倍率字段 int256 化** — 把窄口径的 `uint32`/`float` 倍率全链路升级为大数,消除溢出和精度损失。
2. **鉴定模板 N 行 + 每级增量** — 模板表只存"稀有度档位定义"(行数任意:10/20/30/50 由用户决定),新增"每级增量/公式系数"字段。鉴定时:`最终百分比 = 基础百分比 + 幻境等级 × 每级增量`。组号不再等于等级。
3. **幻境生物属性通用模板行 + 每级增量** — 加一行"通用模板"(约定 幻境等级=0)+ 每级增量字段,实现原作者已声明但未实现的 `GenerateDefaultCreatureConfig`,任意等级从通用行按公式算倍率。

**铁律:C++ 代码里不出现任何具体数字(不硬编码 20、300、1.20 斜率等)。所有行数、系数、公式类型全部是数据库字段值。改手感 = 改表 + `.reload`,永不重编译。**

## 三、现状关键事实(已核实)

### 3.1 已有的地基(原作者埋好但没填)
- `_幻境等级` 表**本就不需要数据**:内存里 `EnsureLevelConfigExists` / `GenerateDefaultLevelConfig` 已按需生成任意等级配置(`HuanJingSystem.cpp:1175-1203`)。
- 装备倍率**已是公式**:`装备属性值=1` 时 倍率 = 幻境等级 × 装备属性倍率系数(`HuanJingSystem.cpp:664-678` `ResolveConfiguredItemAttributeValue`)。
- `HuanJingSystem.h:235-236` **已声明** `EnsureCreatureConfigExists` / `GenerateDefaultCreatureConfig`,但 `.cpp` 中**未实现** — 这是思路③的天然接入口。
- `_幻境生物属性` 支持**通配行**(生物ID/地图/区域 = -1),一行覆盖一个等级的所有生物;匹配按特异度打分取最优(`GetBestMatchConfig`,`HuanJingSystem.cpp:4019-4115`)。
- 鉴定模板生成 SQL 里 `CEIL(pct*(1.20+(组-1)/50))`(`_物品鉴定_模板_20档动态词缀.sql:110`)**已经是"每级增量"公式**,只是在导入时物化了。

### 3.2 数值上限(int256 升级已完成,属性值本身安全)
- 属性值全链路 `uint256`(上限 ≈1.16×10⁷⁷),DB 用 `decimal(65,0)`(上限 ≈10⁶⁵);血量/伤害/装备属性均已 256 位化。
- 100 亿倍(1e10)× 百万级基础值 ≈ 1e16,距上限 50 个数量级,**属性值不会溢出**。
- **窄口是"倍率"这个数字自己的存储/传递类型**,不是属性值。

### 3.3 挡路的窄口径(需扩容)
| 位置 | 现状类型 | 问题 |
|---|---|---|
| `待鉴定物品标记.幻境倍率` | `INT UNSIGNED`(上限 42.9 亿) | 100 亿存不下 |
| C++ 读取(`ItemIdentificationSystem.cpp:3936/4050/5722`) | `Get<uint32>()` | 同上 |
| 传递接口 `ApplyItemAttributeMultiplier(…float…)`(`HuanJingSystem.h:308`) | `float` 倍率 | float 约 1677 万以上丢精度,1 亿倍已不准 |
| `CalculateEnhancedAttributeValue`(`HuanJingSystem.cpp:721`) | `long double` 乘 | 结果超 9e15 丢低位 |
| `equipAttrValue` / `玩家装备属性增强.属性倍率` | `uint32` / `int` | 同 42.9 亿上限 |
| `MirageCreatureAttr::equipAttrValue`(`HuanJingSystem.h:135`) | `uint32` | 同上 |

### 3.4 300 硬编码(必须去掉)
`ItemIdentificationSystem.cpp:1724` 与 `:1858`:
```cpp
if (tmpl.baseAttrMaxValue > 0 && tmpl.baseAttrMaxValue <= 300)  // 百分比模式
else                                                            // 绝对值模式
```
**用数值大小猜模式** — 百分比一超 300 会静默退化成"固定属性值",等级一高必然撞线,口径错乱。
→ 改为显式字段 `属性计算模式`(0=绝对值 / 1=官方百分比),`if` 读字段,不看数值。

## 四、方案设计

### 4.1 倍率 int256 化(思路①)

四层一起改,缺一不可:

| 层 | 改动 |
|---|---|
| DB 字段 | `待鉴定物品标记.幻境倍率` `INT UNSIGNED` → `decimal(65,0)`;`玩家装备属性增强.属性倍率` `int` → `decimal(65,0)` |
| C++ 读取 | `Get<uint32>()` → `Get<uint256>()`(3 处) |
| 传递接口 | `ApplyItemAttributeMultiplier(Item*, float, char)` → 倍率参数改 `uint256`;`equipAttrValue`/`equipAttrMultiplier` 相关结构字段改 `uint256` |
| 计算 | `CalculateEnhancedAttributeValue` 内 `long double` 乘 → 纯整数饱和乘 `SaturatingMultiplyUInt256`(已有,`HuanJingSystem.cpp:336`);百分比运算保留但用 int256 域 |

出口(客户端 tooltip / 面板)保持现有 `ToClientInt32` / 多血条钳制,不动。

### 4.2 鉴定模板:N 行档位 + 每级增量(思路②)

**新表结构** `_物品鉴定_档位模板`(或在现表加字段,见下"决策点"):
- 保留:`组`(=稀有度档位号,非等级)、`随机几率`、`基础属性最小/最大数量`、`追加属性最小/最大数量`、颜色/前后缀、各子系统组关联。
- **新增字段**:
  - `基础百分比最小` / `基础百分比最大`(该档 0 级时的官方属性百分比)
  - `基础每级增量` / `追加每级增量`(幻境等级每 +1,百分比加多少;可为小数,用 `decimal`)
  - `属性计算模式`(0=绝对值 / 1=官方百分比 / 预留 2+)
  - `公式类型`(0=线性 `基础+等级×增量` / 1=指数 `基础×增量^等级`,预留)
- **行数任意**:代码 `SELECT` 出几行就是几行,不认识"20"。

**运行时公式**(C++,无魔法数字):
```
最终百分比 = f(基础百分比, 幻境等级, 每级增量, 公式类型)   // 线性: 基础 + 等级×增量
最终属性值 = 官方参考值 × 最终百分比 / 100                 // int256 域
```
- 幻境等级从 `待鉴定物品标记.鉴定组ID` 关联路径或独立注入(见 4.4 数据流)。
- 抽档:`SELECT WHERE 组=X` 加权 roll(现 `SelectIdentificationTemplate` 逻辑,行数骤减后 O(N) 不再是问题)。
- 删除 300 硬编码,改读 `属性计算模式` 字段。

**SQL 侧**:废弃/改写 `_物品鉴定_模板_20档动态词缀.sql` 的 10 万行物化,改为只插入 N 行档位定义 + 系数字段。旧的 `_补齐3到100组.sql`(绝对值阶梯)一并淘汰。

### 4.3 幻境生物属性:通用模板行 + 每级增量(思路③)

- `_幻境生物属性` 加"通用模板行"(约定 `幻境等级=0` 作为模板锚点)+ 每级增量字段(每个倍率属性一个增量,或一个统一增量列 + 各属性权重,决策点见下)。
- 实现 `GenerateDefaultCreatureConfig(huanJingLevel)`(`HuanJingSystem.cpp` 新增):读通用模板行 → 按公式 `倍率 = 基础倍率 + 等级×每级增量` 生成该等级的 `HuanJingCreatureConfig`。
- `EnsureCreatureConfigExists` 在 `GetBestMatchConfig` 未命中时调用它,即时补配置(仿 `EnsureLevelConfigExists` 现有模式)。
- 关键属性(血量/伤害)到超大倍率时,写**固定值列(uint256)+ 公式**而非 `double` 倍率列,保证 100 亿倍精确不丢位。

### 4.4 数据流(装备鉴定倍率,end-to-end)
```
幻境怪掉落 → OnPlayerLootItem 取拾取者幻境等级
  → 按 _幻境生物属性 通用行公式算倍率(uint256)+ 鉴定组
  → 写 待鉴定物品标记(幻境倍率 decimal(65,0), 鉴定组ID)
玩家鉴定 → 读 待鉴定物品标记(Get<uint256>)
  → ApplyItemAttributeMultiplier(item, uint256 倍率, mode)  // 装备官方属性放大
  → IdentifyItem: SelectIdentificationTemplate(鉴定组)
     → 按档位 + 幻境等级 公式算词缀百分比(int256)
  → CalculateOfficialPercentAttributeValue(int256 域)
穿戴 → ApplyHuanJingEnhancement → ApplyStatModifier(int256)
```

## 五、待决策点(实现时定,默认已给)

1. **鉴定模板:改现表加字段 vs 新建档位表** — 默认:**在现表 `_物品鉴定_模板` 加字段**(复用加载/抽取逻辑,改动最小;旧 10 万行数据由新 SQL 清掉重插 N 行)。
2. **生物属性每级增量粒度** — 默认:**每个倍率属性一个独立增量列**(血量增量、伤害增量分开,手感可控);备选统一增量 + 权重。
3. **公式类型** — 默认:**线性打底**,`公式类型` 字段预留指数,但首版只实现线性。
4. **默认系数** — 给一套合理默认值(如线性斜率使等级 1 亿 ≈ 1 亿倍),用户改表调手感。

## 六、非目标(YAGNI)

- 不改客户端;不动战斗核心 uint256 管线(已完备)。
- 不实现指数公式的具体数学(仅留字段);首版只线性。
- 不做倍率超 1e65(decimal(65,0) 上限)的字符串持久化方案 — 100 亿远未触及。
- 不重构 `mod-challenge-mirage` 的分层世界逻辑(它不做倍率)。

## 七、验证计划

- 编译通过(改 3 模块 C++ + SQL)。
- SQL 导入后 `_物品鉴定_模板` 行数 = N(非 10 万)。
- 服务器启动加载无报错;`.reload` 重载模板生效。
- 手动/GM 命令鉴定:低等级、1 亿级、100 亿级各验一次,属性值符合公式、不溢出、客户端显示正常钳制。
- 幻境生物:进入超高等级幻境,生物血量/伤害符合通用行公式。

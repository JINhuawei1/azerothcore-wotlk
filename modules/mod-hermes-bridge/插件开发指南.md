# Hermes 自定义通信插件开发指南

本文用于后续适配旧插件或开发新插件时，统一接入 Hermes 自定义通信。

目标链路必须是：

```text
客户端 AddOn UI -> HermesDLL.Request -> Hermes 自定义 opcode -> 服务端 Hermes RPC handler -> 直接查库/执行业务 -> Hermes response -> 客户端 UI 显示
```

不要把 Hermes 当成旧 AddOn 聊天命令的桥：

```text
错误链路：客户端 AddOn -> Hermes -> addon.dispatch -> 旧 AddOn prefix -> .中文命令 -> ChatHandler -> 再返回客户端
```

`addon.dispatch` 只能作为临时兼容旧插件的过渡手段。正式接管插件时，读写请求都应注册成明确的 Hermes RPC method。

## 核心原则

1. 每个插件模块使用自己的 method 命名空间，例如 `breakthrough.getAll`、`boundary.getDetail`。
2. 客户端只调用 `HermesDLL.Request(method, payload, callback)`。
3. 服务端在 `HermesBridgeHandler.cpp` 内注册 method，并直接执行查询或业务逻辑。
4. DLL 需要把 method 字符串映射到 methodId，否则客户端发出的请求无法匹配服务端方法。
5. 写操作不能只改数据库，必须复用或等价实现原系统的校验、扣费、属性刷新、技能学习、缓存刷新。
6. 返回格式可以先兼容旧 UI 的文本 payload，后续再逐步升级为更结构化的数据。

```text

```

客户端 DLL：

```text
E:\azerothcore-wotlk\modules\mod-hermes-bridge\client\hermes_bridge_dll.c
```

客户端插件示例：

```text
E:\World of Warcraft335\Interface\AddOns\BreakthroughReforgedUI\BreakthroughReforgedUI.lua
E:\World of Warcraft335\Interface\AddOns\BoundaryUI\BoundaryUI.lua
```

Hermes 返回 JSON 形态：

```json
{
  "jsonrpc": "2.0",
  "id": 100001,
  "result": {
    "schema": "module.action.v1",
    "payload": "..."
  }
}
```

客户端 Lua 回调中读取：

```lua
local responsePayload = msg and msg.params and msg.params.payload
```

注意：当前 DLL 的轻量 JSON 解析不会完整反转义所有 JSON 字符串。多段文本 payload 如果通过 `\n` 返回，客户端需要把 `"\\n"` 还原成真实换行。

新增模块建议使用新的连续段，例如：

```text

400-419  vip

```

同一模块内按功能分组：

```text
getAll / getState / getList / getDetail  放前面
write/apply/upgrade/reset/buy            放后面
```

## 服务端接入步骤

### 1. 增加 methodId

在 `HermesMethodId` 中增加枚举：

```cpp
HERMES_METHOD_MYMOD_GET_ALL = 380,
HERMES_METHOD_MYMOD_UPGRADE = 381
```

### 2. 声明 handler

在 handler 前向声明区域增加：

```cpp
JsonRpcDispatchResult HandleMyModGetAll(WorldSession& session, HermesFrameV2& frame, Json::Value const& request, std::string const& idText, std::string const& method);
JsonRpcDispatchResult HandleMyModUpgrade(WorldSession& session, HermesFrameV2& frame, Json::Value const& request, std::string const& idText, std::string const& method);
```

### 3. 注册 method

在 `HERMES_METHOD_REGISTRY` 里注册：

```cpp
{ "mymod.getAll", HERMES_METHOD_MYMOD_GET_ALL, HERMES_LANE_RPC, HERMES_CODEC_JSON, "active", SEC_PLAYER, 8, HandleMyModGetAll },
{ "mymod.upgrade", HERMES_METHOD_MYMOD_UPGRADE, HERMES_LANE_RPC, HERMES_CODEC_JSON, "active", SEC_PLAYER, 4, HandleMyModUpgrade }
```

字段含义：

```text
Name                客户端调用的方法名
MethodId            Hermes v2 frame methodId
Lane                一般用 HERMES_LANE_RPC
Codec               当前一般用 HERMES_CODEC_JSON
Status              active/smoke 等状态标记
MinSecurity         SEC_PLAYER / SEC_GAMEMASTER
RateLimitPerSecond  限流，写操作要更低
Handler             具体处理函数
```

### 4. 编写 handler

读请求模板：

```cpp
JsonRpcDispatchResult HandleMyModGetAll(WorldSession& session, HermesFrameV2& frame, Json::Value const& request, std::string const& idText, std::string const& method)
{
    (void)frame;
    (void)request;

    Player* player = session.GetPlayer();
    if (!player)
    {
        JsonRpcDispatchResult result;
        result.IsError = true;
        result.Payload = JsonRpcErrorPayload(idText, -32001, "Player is not ready", "PLAYER_NOT_READY", method);
        return result;
    }

    std::ostringstream payload;
    payload << "MYMOD_STATE:" << player->GetGUID().GetCounter();
    return HermesPayloadResult(idText, "mymod.all.v1", payload.str());
}
```

写请求模板：

```cpp
JsonRpcDispatchResult HandleMyModUpgrade(WorldSession& session, HermesFrameV2& frame, Json::Value const& request, std::string const& idText, std::string const& method)
{
    (void)frame;

    Player* player = session.GetPlayer();
    if (!player)
    {
        JsonRpcDispatchResult result;
        result.IsError = true;
        result.Payload = JsonRpcErrorPayload(idText, -32001, "Player is not ready", "PLAYER_NOT_READY", method);
        return result;
    }

    std::string payloadText = ExtractPayloadParam(request);
    uint32 targetId = ParseHermesUInt(payloadText, 0);

    // 这里直接做业务校验和数据库更新，不调用 ChatHandler::ParseCommands。
    // 成功后返回客户端需要刷新的状态。
    std::string response = "[我的模块] [UPGRADE] 1," + std::to_string(targetId);
    return HermesPayloadResult(idText, "mymod.upgrade.v1", response);
}
```

## 客户端 AddOn 接入步骤

### 1. 封装 Hermes 请求

每个插件都应有自己的请求函数，不要在业务按钮里直接散落 `HermesDLL.Request`。

```lua
local hermesRetryFrame

local function ScheduleHermesRetry(delay, callback)
    hermesRetryFrame = hermesRetryFrame or CreateFrame("Frame")
    hermesRetryFrame.elapsed = 0
    hermesRetryFrame:SetScript("OnUpdate", function(frame, elapsed)
        frame.elapsed = frame.elapsed + elapsed
        if frame.elapsed >= delay then
            frame:SetScript("OnUpdate", nil)
            callback()
        end
    end)
end

local function DecodeHermesJsonString(text)
    text = tostring(text or "")
    text = text:gsub("\\n", "\n")
    text = text:gsub("\\r", "\r")
    text = text:gsub("\\t", "\t")
    text = text:gsub('\\"', '"')
    text = text:gsub("\\\\", "\\")
    return text
end

local function DispatchMyModPayload(payload)
    payload = DecodeHermesJsonString(payload)
    if payload == "" then
        return false
    end

    for line in string.gmatch(payload .. "\n", "([^\n]*)\n") do
        line = string.gsub(line, "^%s+", "")
        line = string.gsub(line, "%s+$", "")
        if line ~= "" then
            HandleMyModMessage(line)
        end
    end

    return true
end

local function SendHermesMyModRequest(method, payload, fallback, attempt)
    attempt = attempt or 1
    local bridge = (_G and _G.HermesDLL) or HermesDLL
    if not bridge or type(bridge.Request) ~= "function" then
        if attempt < 8 then
            ScheduleHermesRetry(0.5, function()
                SendHermesMyModRequest(method, payload, fallback, attempt + 1)
            end)
            return true
        end
        if type(fallback) == "function" then
            fallback()
        end
        return false
    end

    local sent = bridge.Request(method, payload or "", function(msg)
        local responsePayload = msg and msg.params and msg.params.payload
        if not DispatchMyModPayload(responsePayload) and type(fallback) == "function" then
            fallback()
        end
    end)

    if sent == nil and attempt < 8 then
        ScheduleHermesRetry(0.5, function()
            SendHermesMyModRequest(method, payload, fallback, attempt + 1)
        end)
        return true
    end

    if sent == nil and type(fallback) == "function" then
        fallback()
        return false
    end

    return true
end
```

### 2. 读请求可以保留旧 fallback

旧插件迁移时，读请求可以先保留 fallback，避免 Hermes DLL 未加载时 UI 完全不可用：

```lua
local function RequestMyModAll()
    return SendHermesMyModRequest("mymod.getAll", "", function()
        SendAddonMessage("OLD_PREFIX", "信息", "WHISPER", UnitName("player"))
    end)
end
```

### 3. 写请求不要 fallback 到旧命令

正式接管后，写操作不要再回落到 `.中文命令` 或旧 AddOn prefix，否则会出现“双通道状态不一致”：

```lua
local function RequestMyModUpgrade(id)
    return SendHermesMyModRequest("mymod.upgrade", tostring(id or 0), nil)
end
```

### 4. UI 按钮只调用业务请求函数

```lua
upgradeButton:SetScript("OnClick", function()
    RequestMyModUpgrade(State.selectedId)
end)
```

不要这样写：

```lua
SendAddonMessage("OLD_PREFIX", "升级 " .. id, "WHISPER", UnitName("player"))
```

## Payload 设计建议

短期适配旧插件时，可以返回旧 UI 已经能解析的文本格式：

```text
[突破系统] [SYSTEM_DATA] ...
[突破系统] [INFO] ...
[突破系统] [SKILLS] ...
```

新插件建议使用模块私有紧凑格式：

```text
MYMOD_STATE:level|exp|points
MYMOD_LIST:item1^name^value~item2^name^value
```

分隔符建议：

```text
|  一级字段
~  多条记录
^  记录字段
,  简单数字列表
;  含中文描述的长字段
```

服务端写 payload 前要清洗字段，避免分隔符破坏解析：

```cpp
std::string SanitizeMyModField(std::string value)
{
    for (char& ch : value)
    {
        if (ch == '|' || ch == '~' || ch == '^' || ch == '\t' || ch == '\r' || ch == '\n')
            ch = '/';
    }
    return value;
}
```

## 写操作必须处理的事项

写操作不是“收到按钮请求后 UPDATE 一下表”。

必须逐项确认：

1. 玩家对象存在：`session.GetPlayer()`。
2. 玩家数据存在，不存在则创建或返回错误。
3. 参数合法，例如物品 ID、技能 ID、等级、页码。
4. 权限合法，例如 GM/玩家权限、职业限制、等级限制。
5. 资源足够，例如金币、点数、材料、货币。
6. 数据库更新要防下溢、防重复、防连点。
7. 需要时使用同步事务，避免连点读到旧余额。
8. 业务效果必须应用到在线 Player，例如属性、技能、光环、称号。
9. 成功和失败都要返回 UI 能显示的结果。
10. 成功后返回最新状态，避免客户端再发多次刷新请求。

## 限流建议

注册 method 时设置合理 `RateLimitPerSecond`：

```text
读 all/detail/list：8-16
分页/详情：16-32
写操作：4-8
GM/debug：1-4
```

写操作不要给过高限流。客户端按钮也应做本地冷却或禁用态，避免短时间连续点击。

## 日志建议

需要直接看 worldserver 控制台时，使用：

```cpp
LOG_INFO("server.loading", "HermesBridge: mymod action account={} guid={} result={}", session.GetAccountId(), player->GetGUID().GetCounter(), resultText);
```

模块内部调试日志可以用模块分类，但不保证直接显示在控制台。

## 适配旧插件的推荐顺序

1. 先找客户端旧 `SendAddonMessage(prefix, command, ...)`。
2. 列出所有 command，分为读操作和写操作。
3. 读操作先迁移为 `module.getAll/getList/getDetail`。
4. 写操作再迁移为 `module.upgrade/buy/apply/reset`。
5. 服务端不要调用旧 `.中文命令`，直接复刻或抽取原业务逻辑。
6. 客户端读操作可短期 fallback，写操作正式接管后不要 fallback。
7. 编译服务端和 DLL。
8. 部署 DLL，重启客户端。
9. 实机打开 UI，逐个按钮验证。
10. 查日志确认不再走 `addon.dispatch`。

## 常见问题

### 客户端请求没有回包

检查：

```text
DLL 是否映射 method 字符串
服务端 HERMES_METHOD_REGISTRY 是否注册 method
methodId 是否服务端和 DLL 一致
WoW 是否加载了最新 HermesBridge.dll
HermesBridge.client 版本是否更新
payload 是否超过 384 字节请求限制
```

### UI 收到数据但不刷新

检查：

```text
callback 是否读取 msg.params.payload
是否处理了 "\\n" 到 "\n" 的反转义
payload tag 是否和旧解析函数匹配
字段分隔符是否被中文描述或名称污染
```

### 写操作数据库变了但属性不生效

说明只改了数据库，没有应用在线 Player 运行时效果。

需要补：

```cpp
sBreakthroughSkillSystem->ApplySkillBonus(player, skillNumber, level);
player->learnSpell(spellId);
player->UpdateAllStats();
player->SendUpdateToPlayer(player);
```

具体调用以对应模块原业务逻辑为准。

### 仍然很卡

检查是否还在走：

```text
Hermes -> addon.dispatch -> 旧 AddOn prefix -> .中文命令 -> ChatHandler
```

正式接管后日志里应看到明确 method，例如：

```text
breakthrough.getAll
breakthrough.learnSkill
boundary.getDetail
```

而不是只有：

```text
addon.dispatch
```

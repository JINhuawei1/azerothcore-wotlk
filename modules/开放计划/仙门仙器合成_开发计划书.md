## 〇、需求来源与原始诉求（用户口述整理）

### 0.1 功能预估原文（玩法蓝图）

**仙门系统**

- 5 大仙门，仙门有大量日常；日常奖励"合成碎片"。
- 碎片主要用来合成仙器主要材料；多件相同物品可合成仙器。
- 仙器共 10 件，独立的仙器槽位；仙器附带高级特效 + 百分比属性 + 套装。
- 独立自制副本，10 大团战 Boss，需组队打，直接掉落成品套装。
- 倍率开放 5000 倍。
- 5 大野外 Boss，上限提高到 2000 级。

**合成系统**

- 主要作用：给官方掉落的装备附加"倍率百分比属性"。
- 相同 5 件装备可合成，附带 10%–1000% 的属性，属性随机，根据"装备鉴定等级编号"决定（编号 20 代表全属性）。
- 人物装备槽位扩展到 42 件。
- 仙门副本掉落"其他定义的装备槽位"，不影响官方装备。
- 不会因为增加直接掉落的套装而导致官方装备无用。

### 0.2 澄清要点（已确认）

1. **交付形态**：本阶段交付"整合开发计划书"，只规划不改代码。
2. **"2000 级"含义**：指 `魔次 / 称号 / 切割 / 回血` 等自定义系统的**配置等级上限**（当前数据只铺到 1000，需扩到 2000），以及与之挂钩的"5 大野外 Boss 系统"数据扩到 2000 级。**不是**角色 `player level`（保持 ≤80）。
3. **仙器槽位 / 42 槽**：**参考飞升系统机制**，新增独立虚拟槽位 + **自定义 UI 界面**，在官方 19 个装备槽之外扩展，不影响官方装备。
4. **5 大仙门 = 全新独立门派系统**：
   - 5 个独立门派，门派各有不同技能、日常任务，玩家可加入。
   - **玩家争夺门主**，当门主有特权。
   - 门主特权：**每天可发布 20 个日常任务**（奖励可自定义选择）、可 **DIY 门派技能**。

## 一、项目背景与目标

本服为成熟的 AzerothCore（WotLK 3.3.5）私服，已具备 15+ 个中文自定义模块与 `int128` 超大数值改造基础。

经代码盘点结论：**上述玩法所需底层"积木"绝大部分已存在**，本计划的核心是把这些模块**编排整合**成统一玩法闭环，并补齐少数缺口（仙门门主玩法、N 件合成、仙器独立槽位 UI、等级数据 1000→2000）。

**总目标**：交付一套"仙门日常 → 产出碎片 → 合成仙器/属性 → 独立槽位装备生效 → 团战副本产出 → 门主争夺"的完整自定义玩法，且不削弱官方装备价值。

## 二、现状盘点：需求 → 现有模块映射

| 需求模块 | 复用的现有资产（路径） | 复用程度 |
| --- | --- | --- |
| 消耗/需求统一框架 | `modules/mod-requirement-template`（`CheckRequirements`/`ConsumeRequirements`，`_模板_需求` 表，支持物品/货币/等级/鉴定等级等条件） | 直接复用，作全局消耗入口 |
| 碎片/货币 | `modules/mod-currency-system`（仙币/神币等 6 币种）+ `modules/mod-material-warehouse`（材料仓库） | 直接复用 |
| 仙门境界/全属性%/渡劫/仙术 骨架 | `modules/mod-cultivation-system`（100 级境界 + 渡劫 Boss + 10 仙术 + 隐藏 Aura 加成） | 复用"等级→%属性→技能"骨架 |
| **独立装备槽位骨架** | `modules/mod-ascension-system`（虚拟背包 `200`、18 独立槽、槽位解锁、`int128` 属性应用、独立槽触发原生套装、客户端 UI 数据下发） | **核心骨架**，仙器槽/扩展槽在其上扩展 |
| 仙器击中特效（DBC 驱动、ID 无关） | `modules/mod-artifact-quest-chain`（`ItemScript::OnCastItemCombatSpell` + `EffectBasePoints_3` 标记法） | 复用其设计模式 |
| 装备追加%属性（穿戴生效、26 属性、GUID 持久化） | `modules/mod-item-attributes` | 合成/仙器属性执行层 |
| 鉴定等级编号（20 档动态词缀，编号 20=全属性） | `modules/mod-item-identification-system`（`_物品鉴定_模板`，20 档） | 直接对应"鉴定等级编号" |
| 套装（穿 N 件触发属性/技能/光环 + 客户端 UI 插件） | `modules/mod-item-sets`（`_物品套装_模板`、`套装物品映射`） | 直接复用 |
| 物品合成 | `modules/mod-item-synthesis`（1 物品→1 物品 + 成功率 + 走需求） | 需扩展"N 件相同→1 件" |
| 自定义 Boss/组队副本 | `modules/mod-challenge-mirage` + `modules/mod-cultivation-system/src/cultivation_chain_boss.cpp` | 复用 BossAI/召唤/组队判定 |
| 魔次/切割/回血/称号 等级系统 | `mod-magic-hit-system` / `mod-cut-system` / `mod-heal-rune-system` / `mod-chenghao-system` | 数据扩展 1000→2000 |
| 超大数值存储 | `modules/int128字段升级`（属性字段→`decimal(39,0)`，配合代码 `int128`） | 底层已就绪 |

### 三条必须遵守的技术现实

1. **官方装备槽 `EQUIPMENT_SLOT_END = 19` 是客户端硬编码**（`src/server/game/Entities/Player/Player.h` 第 678–701 行）→ "42 件槽位"**不能**改官方纸娃娃，只能走**飞升式独立虚拟槽位 + 自定义 UI**。
2. **角色等级硬上限 255**（`src/server/shared/DataStores/DBCEnums.h`：`DEFAULT_MAX_LEVEL=80`、`STRONG_MAX_LEVEL=255`）→ "2000 级"只落在自定义系统配置等级，不动 `player level`。
3. **超大数值底层已铺好**（DB 字段 `decimal(39,0)`、属性应用用 `int128`）→ 5000 倍率、超大%属性叠加在存储层不溢出；实施时确认运行期 `int128` 计算链路一致。

## 三、总体架构：四层骨架 + 一层新玩法

```text
┌─ 新玩法层（需新建）──────────────────────────────────────┐
│  仙门门派系统（5门派 / 门主争夺 / 门主DIY技能 / 门主发20日常） │
│  仙器系统（10件，独立槽，套装，击中特效）                      │
│  N件合成（5件相同→1件，附10%-1000%随机%属性）                │
│  10大团战副本Boss（组队，掉成品套装）                         │
└───────────────────────────────────────────────────────┘
        │ 依赖 / 复用
┌─ ① 槽位骨架 ──────────┐ ┌─ ② 消耗骨架 ─────────────┐
│ mod-ascension-system   │ │ mod-requirement-template   │
│ 虚拟背包200+独立槽+UI   │ │ + mod-currency-system      │
│ → 扩展槽 & 仙器槽       │ │ + mod-material-warehouse   │
└───────────────────────┘ └───────────────────────────┘
┌─ ③ 属性骨架 ──────────┐ ┌─ ④ 内容骨架 ─────────────┐
│ mod-item-attributes    │ │ mod-item-sets（套装+UI）    │
│ mod-item-identification │ │ mod-challenge-mirage(BossAI)│
│ （%属性 + 鉴定编号）     │ │ mod-cultivation（境界/技能）│
└───────────────────────┘ └───────────────────────────┘
        │
└ 数值底层：int128字段升级（decimal39,0）+ worldserver.conf Rate.* ┘
```

**设计原则**：新玩法层只做编排与新逻辑；消耗统一走 `mod-requirement-template`、属性落地统一走 `mod-item-attributes`、套装统一走 `mod-item-sets`、额外槽位统一走 `mod-ascension-system` 机制，避免重复造轮子，并天然满足"不影响官方装备"。

## 四、分阶段开发计划

> 阶段按"先打底层、再做闭环、最后做社交玩法"排序，每阶段可独立编译/导入/验收。

### 阶段 0：数值底座与上限扩展（低风险，纯数据/配置）

- **倍率 5000**：调整 `worldserver.conf` 的 `Rate.XP.*`、`Rate.Drop.Money`、`Rate.Drop.Item.*`、`Rate.Honor` 等；确认 `src/server/game/World/World.cpp` `getRate` 无 `clamp`（列为验收项）。
- **等级 1000→2000**：复用现成"序列生成脚本"模式（`modules/mod-magic-hit-system/sql/world/_魔次神石_统一1_1000数据.sql` 的临时表 + `CROSS JOIN`）。
  - 魔次：生成上限 `1000→2000`，续接 `item_template(420000+lvl)`、`_模板_需求(420000+lvl)`、`creature_template`/`creature_loot_template`，数值曲线外推。
  - 切割 / 回血 / 称号：各自把"每级一行"配置补到 2000 级，检查 conf/代码内是否有 `≤1000` 上限。
- **5 大野外 Boss 数据到 2000**：随魔次脚本生成；确认其余野外 Boss 系列一并外推。
- **验收**：抽查 lvl=1500/2000 的材料/需求/Boss/掉落齐全；各系统能升到 2000 级且数值生效。

### 阶段 1：扩展装备槽 + 仙器槽框架（核心骨架）

- 以 `modules/mod-ascension-system` 为蓝本：复用虚拟背包 `200`、`OnPlayerCanEquipItem`、`int128` 属性应用、`CanItemRemove`、独立槽触发原生套装、`SendAscensionDataToClient`。
- **槽位规划**（可配置）：扩展槽总数对齐"42"目标 = 官方 19 + 扩展 23，其中划出 **10 个仙器专用槽**（类别限定为仙器物品）+ 其余通用扩展槽；以表配置"槽位类型 + 解锁需求(需求模板id)"。
- **自定义 UI 界面**：参考 `mod-item-sets` 客户端 UI 插件 + 飞升数据下发，开发"仙器/扩展装备"面板 AddOn（服务端下发 + AddOn 渲染槽位/拖拽穿戴）；素材走 `agent-harness` PNG→TGA 流程。
- **验收**：扩展槽穿/卸、属性增减、登录恢复、不污染官方槽、UI 正确显示。

### 阶段 2：合成系统增强（N 件相同 → 1 件 + 随机%属性）

- 扩展 `modules/mod-item-synthesis`：新增"N 件相同→1 件"配方表（数量、成功率、走需求模板）。
- 属性落地：合成成功后调用 `mod-item-attributes` 写入随机%属性（10%–1000%），按 `mod-item-identification-system` 的鉴定等级编号决定属性条数/种类（编号 20=全属性）。
- 平衡：只在官方掉落基础上"附加百分比"，不替换基础值 → 官方装备不作废。
- **验收**：5 件相同→合成→产出带随机%属性，鉴定编号驱动范围正确，穿戴生效。

### 阶段 3：仙器系统（10 件 + 套装 + 击中特效）

- 仙器物品：`item_template` 定义 10 件（各对应一个仙器槽类别）；%属性走 `mod-item-attributes`；套装走 `mod-item-sets`。
- 高级特效：沿用 `mod-artifact-quest-chain` 的 **DBC 驱动 + `EffectBasePoints_3` 标记 + `OnCastItemCombatSpell`（ID 无关）**；DBC 生成走 `agent-harness/patch_toolchain/wanjian`（`az patch ...`）。
- 材料来源：仙门日常碎片 → 合成（阶段 2）→ 仙器材料 → 合成仙器。
- **验收**：10 件仙器可穿戴、套装分级触发、击中特效按战力%生效、与官方装备并存。

### 阶段 4：仙门门派系统（5 门派 + 门主争夺 + 门主特权）【最大新建项】

> 📐 完整策划（5 门派定位 / 30 个门派技能 / 10 类日常模板 / 奖励白名单 / 数据表 / ID 规划）见独立文档：`仙门门派_技能_日常_详细设计.md`

**5 大仙门概览**（门派技能**全为被动**；每个门派挂钩一个现有系统作流派特色）：

| 门派 | 定位 | 核心玩法 | 挂钩系统 |
| --- | --- | --- | --- |
| 太虚剑宗 | 物理爆发（被动触发剑气/流血） | 攻击强度·暴击·切割 | `mod-cut-system` |
| 万象丹鼎 | 采集+炼丹（吃属性丹无限提升属性） | 采集·炼丹·永久属性累积 | 官方采集专业 + `mod-requirement-template` |
| 九霄符箓 | 法术爆发（被动触发多重/连锁） | 法强·急速·魔次 | `mod-magic-hit-system` |
| 不灭体殿 | 坦克/反伤/超耐久 | 耐力·护甲·超大生命 | `int128` 超大生命 |
| 御灵魂宗 | 武魂召唤（门派等级→多武魂+继承提升） | 武魂继承·多召唤 | `mod-wuhun-system` |

- **门派与成员**：新建 `_仙门_门派(5)`、`_仙门_成员` 表；加入/退出/查询走 NPC Gossip + `.仙门` 命令；门派独立技能集复用 `mod-cultivation-system` 的"等级解锁技能 + 学习/遗忘"骨架。
- **门主争夺**：**每日 0:00 按门派当日贡献结算，贡献最高者当选；结算后清零贡献**，次日重新争夺；`_仙门_门主` 记录当前门主与结算时间。
- **门主特权**：
  - **每天发布 20 个日常**：门主从"日常模板池"选任务 + 自选奖励（受白名单约束）→ 写入 `_仙门_日常_当日` 供成员接取，每日重置。
  - **门派技能 10 选 5**：每门派 10 个被动技能池，门派修为上限 100、**每 10 级 1 个解锁名额（玩家自选解锁任一技能）**；门主从已解锁技能选 5 个生效（**可随时改，玩家小退生效**）；成员实际生效 = 门主选定 ∩ 自己已解锁。门派技能**全为被动**。
- **日常奖励 = 合成碎片**：完成发放碎片，接入合成链。
- **日常框架**：优先复用核心 `quest_template` daily 标志 + 每日重置；自定义部分用"模板池 + 当日实例表"。
- **验收**：5 门派可加入、门主每日 0:00 按贡献争夺、门主能发 20 日常并自选奖励、门主能从已解锁技能选 5 个生效（改后玩家小退生效）、成员能完成日常拿碎片并按修为逐级解锁技能加成、每日重置正确。

### 阶段 5：10 大团战副本 Boss（组队 + 掉成品套装）

- 复用 `mod-challenge-mirage` 的 BossAI/进入/组队判定 + `cultivation_chain_boss` 的召唤/归属。
- 进入：优先复用现有地图坐标/副本（避免新建客户端 `.map`）；组队人数/队长校验走 `mod-requirement-template`（`需要队伍人数`/`需要是队长` 字段已支持）。
- 掉落：`creature_loot_template` 配成品套装件（套装走 `mod-item-sets`）。
- **验收**：需组队进入、Boss 战正常、掉成品套装且套装效果生效。

## 五、关键技术决策

1. **仙器/扩展槽 = 飞升系统扩展，不改官方 19 槽**：统一走虚拟背包 `200` + 自定义 UI，绕过客户端硬编码，天然"不影响官方装备"。
2. **统一消耗入口**：仙门升级/合成/解锁槽/仙器升级一律走 `sRequirementSystem`，配置在 `_模板_需求`。
3. **统一属性落地**：合成/仙器/鉴定%属性统一走 `mod-item-attributes`；超大数值用 `int128`/`decimal(39,0)`。
4. **特效 ID 无关**：仙器特效沿用 DBC `EffectBasePoints_3` 标记法，C++ 不绑死 spellId。
5. **等级扩展用生成脚本**：1000→2000 改"序列生成 SQL"上限并外推，不手写 2000 行。
6. **门主 DIY 受控**：自选奖励/自定义技能必须白名单 + 数值上下限，防经济崩坏与无敌技能。

## 七、风险与待确认项

- **客户端 UI 工作量**：仙器/扩展装备面板、门主面板均需 AddOn 开发，是最大非 SQL 工作量，建议独立小版本迭代。
- **超大数值回归**：5000 倍 + 2000 级 + %叠加 + `int128` 同时叠加，需重点回归伤害/经验/掉落是否溢出。
- **门主玩法规则待细化**：争夺方式（PvP/积分/贡献）、任期/罢免、奖励白名单范围、DIY 技能可调参数边界 → 阶段 4 开工前定为规则表。
- **平衡性**：合成%属性最高 1000% + 仙器 + 境界% + 各等级系统叠加，需一张"数值总表"评估战力曲线。
- **"42 槽"精确构成**：官方 19 + 扩展 23（含 10 仙器槽）为建议拆分，阶段 1 据实调整。

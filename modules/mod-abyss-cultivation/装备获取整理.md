# mod-abyss-cultivation 装备获取整理

## 1. 文档目的

本文用于整理 `mod-abyss-cultivation` 当前版本中各类装备、遗物、神器的实际获取方式。

本整理以当前模块 SQL 配置与 C++ 运行时代码为准，不以策划文案或预留字段为准。

| --- | --- | --- | ---: | --- |

## 4. 当前实际获取逻辑

### 4.1 章节遗物

章节遗物使用 `950001-950074`。

当前实现里，章节遗物主要来自章节的腐化任务奖励。

腐化任务会：

- 直接发放本章遗物
- 额外提供一件本章底材自选奖励

如果玩家包里已有遗物物品，也可以通过 `COLLECT_RELIC:<物品ID>` 指令将其转成收藏，并从背包中扣除该物品。

实际效果上，章节推进同步时，在完成腐化任务后，系统还会把本章遗物直接写入玩家收藏，并在主遗物槽为空时自动放入主槽。

### 4.2 阶段神器

阶段神器使用 `960001-960006`。

当前实现不是 Boss 掉落，也不是现成合成台逻辑。

实际规则为：

- 按幕检查玩家是否收齐该幕全部章节遗物
- 若收齐，则自动解锁该幕对应阶段神器
- 若玩家当前还没有阶段神器，则自动装备到阶段神器槽

也就是说，阶段神器当前是“收集成就式自动解锁”。

### 4.3 终极神器

终极神器使用 `970001`。

当前实现同样不是普通掉落，也不是现成合成流程。

实际规则为：

- 玩家最高章节达到 `74`
- 玩家已拥有全部 `6` 个阶段神器
- 满足后自动解锁终极神器
- 若玩家当前还没有终极神器，则自动装备到终极神器槽

需要注意的是，配置文案里写了“六神器齐全 + 74章全通 + 终局渡劫事件”，但当前代码里没有额外校验“终局渡劫事件”。

### 4.4 正传底材

正传底材使用 `990001-990054`。

它们是装备类型 `1`，来源模式为 `1`。

当前获取来源有三条：

- 锚点首领奖励池
- 最终首领奖励池
- 深渊首领奖励池

除此之外，腐化任务完成时还会给本章一件“底材自选奖励”，也是从这类底材池里选。

### 4.5 腐化底材

腐化底材使用 `991001-991054`。

它们由正传底材派生，来源模式为 `3`，主要用于腐化模式奖励池。

当前实际来源：

- 腐化模式下击败深渊首领后，从深渊首领奖励池中抽取

### 4.6 轮回底材

轮回底材使用 `992001-992054`。

它们由正传底材进一步派生，来源模式为 `4`，主要用于轮回模式奖励池。

当前实际来源：

- 轮回模式下击败深渊首领后，从深渊首领奖励池中抽取

### 4.7 唯一装备

唯一装备使用 `980001-980012`。

它们是装备类型 `2`，对接类型 `5`。

当前代码中，这批装备统一标记为：

- `是否来自秘藏首领 = 1`
- `是否需要碎片 = 0`

实际获取方式不是传统 `creature_loot_template` 掉落表，而是：

1. 玩家击杀锚点首领或最终首领
2. 系统按章节配置的“秘藏基础概率 / 秘藏保底次数”尝试召唤秘藏首领
3. 玩家击杀秘藏首领
4. 模块运行时代码从秘藏奖励候选池中抽取唯一装备
5. 直接 `AddItem` 发到玩家背包

也就是说，当前唯一装备属于“秘藏首领运行时发奖”，不是“静态掉落表”，也不是“碎片合成”。

## 5. Boss 与奖励池关系

### 5.1 锚点首领 / 最终首领

当前主要候选奖励为：

- 正传底材 `990001-990054`

不会直接产出唯一装备。

它们的另一个作用是触发秘藏首领召唤判定。

### 5.2 深渊首领

当前主要候选奖励为：

- 正传底材
- 腐化底材
- 轮回底材
- 非秘藏来源的装备候选

具体会掉到哪个来源模式，取决于玩家当前所在模式。

### 5.3 秘藏首领

当前主要候选奖励为：

- 唯一装备 `980001-980012`
- 对接类型为 `5` 的候选物品

秘藏首领是唯一装备的核心来源。

## 6. 模式与掉落对应关系

| 模式 | 模式值 | 主要奖励倾向 |
| --- | ---: | --- |
| 正传 | `1` | 正传底材 |
| 深渊 | `2` | 正传底材 + 深渊模式唯一装备候选 |
| 腐化 | `3` | 腐化底材 + 更高品质候选 |
| 轮回 | `4` | 轮回底材 + 更高品质候选 |

补充说明：

- 锚点首领和最终首领的奖励逻辑更偏向章节基础奖励
- 深渊首领负责主要装备奖励推进
- 秘藏首领负责唯一装备

## 8. 底材数量结构

### 8.1 正传底材

每幕 9 件，共 6 幕，共 `54` 件。

部位顺序固定为：

- 物理武器
- 法器
- 头部
- 胸甲
- 腰带
- 靴子
- 戒指
- 饰品
- 披风

### 8.2 腐化底材

由正传底材整体派生而来，共 `54` 件。

### 8.3 轮回底材

由正传底材整体派生而来，共 `54` 件。

## 9. 任务线与奖励关系

当前章节任务链可以概括为：

| 任务类型 | 含义 | 作用 |
| --- | --- | --- |
| `1` | 起始任务 | 开启章节流程 |
| `2` | 官方任务 | 解锁正传模式 |
| `3` | 正传任务 | 解锁深渊模式 |
| `4` | 深渊任务 | 解锁腐化模式 |
| `5` | 腐化任务 | 解锁轮回模式，并发放章节遗物与底材自选 |

其中，装备获取最关键的是任务类型 `5`：

- 发本章章节遗物
- 提供本章底材自选
- 推动后续阶段神器 / 终极神器的自动解锁

## 10. 当前代码与配置文案的差异

### 10.1 “碎片合成”字段已预留，但唯一装备当前不是合成获得

装备模板中有 `是否需要碎片` 字段，客户端也保留了 `[碎片合成]` 的显示分支。

但当前唯一装备 `980001-980012` 全部配置为 `是否需要碎片 = 0`。

当前代码中也没有查到这批唯一装备的实际碎片合成发放流程。

因此当前应认定：

- 字段已预留
- UI 已预留
- 但玩法尚未真正落地

### 10.2 终极神器文案要求“终局渡劫事件”，代码未严格校验

配置文案描述：

- 六神器齐全
- 74章全通
- 终局渡劫事件

当前代码实际校验只有：

- `highestChapter >= 74`
- 玩家已拥有全部阶段神器

所以文案与实现尚未完全一致。

### 10.3 掉落不是完全依赖 AzerothCore 原生 loot 表

虽然 AzerothCore 原生有 `*_loot_template` 体系，但本模块已明确把自定义深渊 / 秘藏首领奖励切换为 C++ 运行时代码直接发放。

因此看本模块奖励时，必须优先看：

- `sql/world/11_装备模板.sql`
- `sql/world/13_任务对接.sql`
- `sql/world/17_掉落模板对接.sql`
- `src/mod_abyss_cultivation.cpp`

而不能只看 `creature_loot_template`。

## 11. 建议给策划/开发的口径

如果只讲当前版本实际效果，建议统一用下面这套说法：

- 章节遗物：通过腐化任务获得
- 阶段神器：收齐本幕遗物后自动解锁
- 终极神器：六个阶段神器齐全后自动解锁
- 普通底材：主要由章节首领和深渊首领奖励产出
- 唯一装备：由秘藏首领产出
- 碎片合成：字段与展示已预留，但当前唯一装备尚未正式采用该获取方式

## 16. 底材的真实用途

### 16.1 当前定义

虽然系统里一直把 `990xxx / 991xxx / 992xxx` 这批装备称为“底材”或“胚”，但按当前代码实现，它们并不是纯材料，而是：

- 可直接进入 `item_template`
- 可直接穿戴
- 可直接触发套装件数统计
- 可作为正传 / 腐化 / 轮回三条装备成长线的主要散件来源

也就是说，当前版本里的“底材”更准确地说，是：

- `套装散件本体`
- `章节常规装备池`

而不是“只用于后续合成的消耗材料”。

### 16.2 当前能做什么

底材在当前版本中主要承担 4 个用途：

1. 作为玩家的可穿戴装备来源  
   正传、腐化、轮回三种模式都会产出对应底材，玩家拿到后可以直接装备使用。

2. 作为套装件数载体  
   底材会被赋予内部 `套装ID`，穿戴时由 C++ 统计 2 件 / 4 件效果。

3. 作为模式成长分层  
   `990xxx` 对应正传底材，`991xxx` 对应腐化底材，`992xxx` 对应轮回底材，三者装等和预算逐步提升。

4. 作为任务奖励自选池  
   腐化任务完成后，会从本章普通底材池里提供一件自选奖励。

### 16.3 当前不能做什么

按现有代码，底材目前没有真正形成下面这些玩法：

- 没有看到“消耗底材合成唯一装备”的实际逻辑
- 没有看到“底材升阶为唯一装备”的实际逻辑
- 没有看到“底材进阶打造台”或“碎片锻造台”的实际逻辑

因此如果只按当前版本解释，建议不要再把底材对外描述成“纯合成材料”，否则会和实际玩法不符。

## 17. 套装系统现状

### 17.1 为什么会感觉“缺失了套装”

这个感觉是对的。

当前套装系统属于：

- `配置层已做`
- `件数统计已做`
- `部分属性效果已做`
- `完整玩法效果未做完`

所以它不是完全没有，而是“半成品状态”。

### 17.2 已经完成的部分

当前已完成内容包括：

1. 套装配置表  
   世界库里有 `_深渊套装配置`，当前已扩展为每幕、每模式的 `2 / 4 / 6 / 8` 四档效果。

2. 套装ID赋值  
   正传、腐化、轮回底材都被赋了内部 `套装ID`。

3. 穿戴统计  
   玩家登录、装备、背包调整时，C++ 会重新统计当前穿了几件同套装装备。

4. 2件 / 4件 / 6件 / 8件基础加成  
   当前套装系统已经可以施加多档属性类效果，例如：
   - 全属性
   - 暴击等级
   - 急速等级
   - 攻击强度
   - 法术强度
   - 生命值百分比
   - 全伤害百分比

### 17.3 仍未完整落地的部分

当前未完整落地的部分主要是：

1. `4件特殊效果` 仅停留在配置层  
   例如：
   - `套装_灰烬回响`
   - `套装_腐焰噬魂`
   - `套装_征魂爆发`
   - `套装_归墟不灭`

   这些特殊效果标识目前主要还停留在配置表中，并没有像遗物那样全面接入运行时触发逻辑。

2. 套装表现不走客户端原生 ItemSet/DBC  
   当前是 C++ 直接改玩家属性，不是 WoW 原生套装系统，所以视觉表现和提示感会偏弱。

3. 唯一装备不参与套装  
   12 件唯一装备大多没有 `套装ID`，因此不会和底材一起形成完整“毕业套 + 专属件混搭体系”。

4. 文档中仍把“真正的套装系统”列为未完成项  
   这说明当前作者自己也把它视为“未最终完工”的功能。

### 17.4 本次补上的完善

这次已补上一批原来“表里有、代码里没真正吃满”的内容：

1. `2件法术强度`  
   原实现把它错误地当成了主手伤害加值，现在已改为真正的法术强度加成。

2. `4件伤害加成百分比`  
   原配置表里有该字段，但运行时没有真正施加；现在已经接入套装生效与移除逻辑。

3. 套装特殊效果入口条件  
   原来很多运行时触发点只会检查“局内状态 / 遗物是否激活”，套装就算配置了 4 件特殊效果，也可能根本进不到触发逻辑。现在这层入口已经打通。

4. 第一批高阶套装特殊效果  
   当前已经补入一批较稳定、可直接落地的高阶特殊效果，包括：
   - `套装_腐焰噬魂`
   - `套装_灰烬回响`
   - `套装_轮焰双爆`
   - `套装_征魂爆发`
   - `套装_寒夜冻结`
   - `套装_玄霜封印`
   - `套装_古神觉醒`
   - `套装_神蚀吸收`
   - `套装_烬世叠加`
   - `套装_终焉天罚`
   - `套装_血誓不灭`
   - `套装_归墟不灭`

5. 临时成长类/保命类套装状态  
   当前已经补入：
   - `古神觉醒` 的 10 秒全属性提升
   - `烬世叠加` 的战斗内逐层成长与离战重置
   - `血誓不灭 / 归墟不灭` 的死亡保护逻辑

6. 客户端展示  
   当前套装 tooltip 已同步扩展为显示 `2 / 4 / 6 / 8` 四档描述。

### 17.5 仍建议后续继续完善的方向

如果后续要把套装系统补到“完整可玩”，建议按下面顺序推进：

1. 把 `4件特殊效果` 一条条接入运行时逻辑  
   虽然已经接入第一批，但配置表里仍有部分效果还只是“近似实现”或“尚未实现完整版本”。

2. 给套装提供更明确的客户端展示  
   例如在 UI 中单独展示当前已激活的 2 件 / 4 件效果。

3. 重新梳理“底材、套装、唯一装备”的终局关系  
   当前这三者并没有完全形成闭环。

4. 决定底材未来到底是：
   - 继续当作直接穿的套装散件
   - 还是进一步改造成真正的合成材料

## 18. 当前建议口径更新

如果以后再向策划、测试或其他开发解释当前系统，建议用下面这套更准确的口径：

- 底材：当前版本中是“可直接穿戴的套装散件”，不是纯材料
- 套装：当前已具备基础 2 件 / 4 件属性效果，但特殊效果尚未全部落地
- 唯一装备：独立于底材套装线，主要由秘藏首领提供
- 遗物 / 神器：走章节奖励与自动解锁线，不直接并入底材套装体系

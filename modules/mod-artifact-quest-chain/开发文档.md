# 神器任务链开发文档

## 目标

在 `modules\神器任务链` 中设计一套 16 阶神器任务链。本文档只记录设计与实现依据，后续再按本文档生成 SQL、DBC 脚本或导入数据库。

本阶段不导入数据库、不修改 DBC、不执行编译或构建。

## 任务链规则

16 个任务由同一个任务 NPC `91001` 接取和交付。

第 1 阶任务：

- 任务 ID：`30001`
- 需求：`90017` 初醒神核 x100
- 奖励：`90001` 神器·初醒 x1

第 2 到第 16 阶任务：

- 当前阶任务 ID：`30000 + 阶数`
- 需求：上一阶神器 x1 + 当前阶材料 x100
- 奖励：当前阶神器 x1

示例：

| 阶 | 任务 ID | 需求 | 奖励 |
| ---: | ---: | --- | --- |
| 2 | `30002` | `90001` 神器·初醒 x1，`90018` 玄铁神纹 x100 | `90002` 神器·玄纹 x1 |
| 16 | `30016` | `90015` 神器·万象 x1，`90032` 终焉神格 x100 | `90016` 神器·终焉 x1 |

任务链应在 `quest_template_addon` 中使用 `PrevQuestID` 和 `NextQuestID` 串联，`quest_template.RewardNextQuest` 也同步指向下一阶任务。

## Spell.dbc 规划

总共创建 80 个技能，ID 为 `381001..381080`。

这些技能不再提供全属性、总伤害、最大生命等百分比属性加成。神器已经在 `item_template.stat_value1..10` 上拥有极高固定属性，因此技能部分只负责战斗特效、触发玩法、视觉表现和技能说明。

每阶神器绑定 5 个技能：

- 5 个技能全部为击中特效，统一写入 `spelltrigger=2`。
- 不设计主动释放技能，玩家只需要装备神器并参与战斗即可触发。
- DBC 中不写超大固定伤害数值，避免超过 signed int32 最大约 21 亿的限制。
- DBC 的 `EffectBasePoints_1..3`，也就是表格工具中显示的效果基础值字段 `[81]..[83]`，负责控制伤害比例、副效果参数和技能类型。
- 技能必须尽量像官方火球术一样由 Spell.dbc 原生效果驱动；技能 ID 只作为数据行主键，不作为脚本逻辑条件。
- C++ 只做通用扩展，不硬编码技能 ID、不使用 `spellId - 381001`、不依赖 `spell_script_names` 逐 ID 绑定。
- 如果使用脚本增强，优先采用 `ItemScript::OnCastItemCombatSpell` 接入官方物品击中特效流程，脚本通过 DBC 字段识别神器技能，而不是通过技能 ID 识别。

### DBC 实现规则

生成 `Spell.dbc` 时优先克隆现有同类型技能模板，再修改 ID、名称、说明、视觉、基础数值和触发字段。不要从零猜测所有目标字段，目标选择、范围、弹道等字段应继承稳定模板后再定向调整。

DBC 负责让技能能被物品击中触发、显示说明、播放视觉，并控制伤害比例、技能类型和副效果参数。`EffectBasePoints_1..3` 不写最终伤害值，只写小整数参数，因此不会受到 21 亿伤害值上限影响。

字段约定：

| 字段 | 表格工具列号 | 用途 | 说明 |
| --- | --- | --- | --- |
| `EffectBasePoints_1` | `[81]` | 主伤害比例 | 万分比，`10000 = 100%`，`100 = 1%`。脚本用它计算 `神器战力 * 比例 / 10000`。 |
| `EffectBasePoints_2` | `[82]` | 副效果参数 | 噬魂回响写治疗比例，时空禁锢写定身秒数，其他技能可写 `0`。 |
| `EffectBasePoints_3` | `[83]` | 神器技能标记 + 类型编码 | 使用 `9100101..9100105`。前缀 `91001` 表示神器任务链，最后两位表示技能类型。脚本根据这个字段决定是否进入神器逻辑，不根据技能 ID 判断。 |

注意：AzerothCore 代码注释中 `EffectBasePoints` 按 0 基字段标为 `80-82`，表格工具通常按 1 基列号显示为 `[81]..[83]`，两者指的是同一组三个效果基础值字段。

| 技能 | 推荐 DBC 效果 | 关键字段要求 |
| --- | --- | --- |
| 天雷裁决 | `SPELL_EFFECT_DUMMY` 或低数值伤害壳 | 目标为当前攻击目标，视觉使用雷击/落雷主题；`EffectBasePoints_1` 写自然伤害比例，`EffectBasePoints_3 = 9100101`。 |
| 万剑归宗 | `SPELL_EFFECT_DUMMY` 或低数值伤害壳 | 目标为当前攻击目标，视觉使用剑气/刀光/冲击主题；`EffectBasePoints_1` 写物理或神器伤害比例，`EffectBasePoints_3 = 9100102`。 |
| 时空禁锢 | `SPELL_EFFECT_DUMMY` + 可选定身光环 | `EffectBasePoints_1` 写奥术伤害比例；`EffectBasePoints_2 = 2` 表示定身2秒；`EffectBasePoints_3 = 9100103`。 |
| 噬魂回响 | `SPELL_EFFECT_DUMMY` 或低数值吸血壳 | `EffectBasePoints_1` 写暗影伤害比例；`EffectBasePoints_2 = 5000` 表示治疗量为实际伤害的50%；`EffectBasePoints_3 = 9100104`。 |

### 脚本计算规则

脚本必须采用 ID 无关方案。不要写 `spellId - 381001`、不要假设 5 个技能连续、不要按 ID 范围判断技能类型。

官方技能改 ID 后仍能使用，核心原因是技能效果由 Spell.dbc 当前行描述，核心通用法术系统按这行数据执行。这里也按同样思路设计：能由 DBC 原生效果完成的部分全部交给 DBC；脚本只作为物品击中特效流程中的增强逻辑读取 DBC 参数，不作为固定 ID 入口。

脚本从 DBC 读取参数：

```cpp
int32 damagePct = GetSpellInfo()->Effects[EFFECT_0].CalcValue(); // DBC EffectBasePoints_1
int32 miscValue = GetSpellInfo()->Effects[EFFECT_1].CalcValue(); // DBC EffectBasePoints_2
int32 marker    = GetSpellInfo()->Effects[EFFECT_2].CalcValue(); // DBC EffectBasePoints_3
```

最终伤害只由玩家属性和 DBC 比例决定：

```cpp
uint64 damage = artifactPower * damagePct / 10000;
```

`marker` 决定是否进入神器逻辑，以及使用哪种伤害学派和副效果。后续如果技能 ID 从 `381001..381080` 改成其他 ID，只要新 DBC 行的 `EffectBasePoints_1..3` 参数正确，并且装备模板引用了新 ID，C++ 脚本不需要修改。

神器战力建议按玩家当前属性动态计算：

```text
基础五维 = 力量 + 敏捷 + 耐力 + 智力 + 精神
神器评级 = 真实伤害 + 切割伤害 + 命中等级 + 攻击强度 + 法术强度
神器战力 = 基础五维 + 神器评级
```

后续实现时，自定义属性 `真实伤害`、`切割伤害` 的读取方式以本地核心实际字段为准；如果核心没有通用读取接口，需要在神器模块内封装统一取值函数，避免每个技能重复写属性读取逻辑。

脚本发放规则：

- 天雷裁决：对当前目标造成自然伤害。
- 万剑归宗：对当前目标造成物理或神器伤害；如果本地核心支持自定义 `切割伤害`，优先接入切割伤害类型。
- 时空禁锢：对当前目标造成奥术伤害，并按 `EffectBasePoints_2` 尝试附加定身；目标免疫控制时只造成伤害。
- 噬魂回响：对当前目标造成暗影伤害，随后按 `EffectBasePoints_2` 治疗施法者。
- 终焉星爆：对当前目标造成奥术爆发伤害，作为低频击中触发的大特效。

所有脚本计算建议使用 `uint64` 或更高精度中间值。DBC 只保存比例，最终伤害由脚本运行时计算，调用核心伤害接口前再按接口支持范围做上限保护，避免整数溢出。

### 官方式 ID 无关生效规则

火球术这类官方技能改 ID 后仍能生效，是因为核心通用法术系统读取的是 Spell.dbc 当前行的效果字段，例如 `Effect`、`EffectBasePoints`、目标、学派、视觉、施法时间等。只要新 ID 的 DBC 行完整，核心就能按这行数据施放技能。

官方技能的基本执行流程：

1. 调用方传入一个 `spellId`。
2. 核心通过 `sSpellMgr->GetSpellInfo(spellId)` 找到 Spell.dbc 中对应的 `SpellInfo`。
3. 核心读取这行 DBC 的 `Effect_1..3`。
4. 每个 `Effect` 分派到通用处理函数。
5. 例如 `SPELL_EFFECT_SCHOOL_DAMAGE = 2` 会进入 `Spell::EffectSchoolDMG`，伤害基础值来自 DBC 的 `EffectBasePoints`。
6. 因此，只要把火球术 `133` 复制成 `999`，并且 `999` 这一行 DBC 字段完整，核心就会按 `999` 这一行施放法术。

官方物品击中特效流程：

1. 玩家造成命中伤害后，核心进入 `Player::CastItemCombatSpell`。
2. 核心遍历装备模板的 `spellid_1..5`。
3. 只处理 `spelltrigger = 2` 的击中特效。
4. 通过 `sSpellMgr->GetSpellInfo(spellid)` 读取 Spell.dbc 当前行。
5. 按 `spellppmRate` 或 DBC 触发率计算是否触发。
6. 触发成功后调用 `CastSpell(target, spellInfo->Id, ...)`。
7. 后续仍由 Spell.dbc 当前行的 `Effect`、目标、视觉、学派等字段决定法术表现。

对应核心位置：

- `Player::CastItemCombatSpell`：`src\server\game\Entities\Player\Player.cpp`
- `SPELL_EFFECT_SCHOOL_DAMAGE` 分派：`src\server\game\Spells\SpellEffects.cpp`
- `Spell::EffectSchoolDMG`：`src\server\game\Spells\SpellEffects.cpp`
- `Spell::EffectDummy`：`src\server\game\Spells\SpellEffects.cpp`
- `ItemScript::OnCastItemCombatSpell`：`src\server\game\Scripting\ScriptDefines\ItemScript.h`

神器技能也按这个原则设计：

- 技能 ID 只作为 Spell.dbc 行主键。
- `item_template.spellid_1..5` 只负责引用当前技能 ID。
- 技能实际效果尽量由 Spell.dbc 原生字段完成。
- C++ 不写固定技能 ID。
- C++ 不要求 `381001..381080` 连续。
- C++ 不要求每个技能 ID 在 `spell_script_names` 中逐条绑定。

如果只使用 DBC 原生效果，例如 `SPELL_EFFECT_SCHOOL_DAMAGE`、`SPELL_EFFECT_HEALTH_LEECH`、`SPELL_EFFECT_APPLY_AURA`，则不需要任何 `spell_script_names`。这种方式最接近火球术：换技能 ID 后，只要 `item_template.spellid_1..5` 指向新 ID，新 DBC 行完整，技能就能继续触发和生效。

如果必须实现 DBC 原生系统做不到的“按神器战力百分比计算最终伤害”，则在官方物品击中特效流程上扩展，不使用逐 ID 绑定：

- 给神器武器的 `item_template.ScriptName` 设置一个统一物品脚本名，例如 `item_artifact_chain_weapon`。
- 实现 `ItemScript::OnCastItemCombatSpell`。
- 核心命中后准备触发物品 spell 时，会把 `player`、`victim`、`spellInfo`、`item` 传入这个 Hook。
- 脚本读取该技能 Spell.dbc 当前行参数。
- 只有满足神器标记的技能才进入神器逻辑。
- 其他技能，包括火球术、寒冰箭等官方技能，直接返回 `true`，继续走官方原生逻辑。

神器标记不使用技能 ID，使用 DBC 参数：

```cpp
SpellInfo const* spellInfo = ...;
int32 damagePct = spellInfo->Effects[EFFECT_0].CalcValue(); // EffectBasePoints_1
int32 miscValue = spellInfo->Effects[EFFECT_1].CalcValue(); // EffectBasePoints_2
int32 marker    = spellInfo->Effects[EFFECT_2].CalcValue(); // EffectBasePoints_3

if (marker < 9100101 || marker > 9100105)
    return; // 不是神器技能，直接交给核心原生逻辑
```

推荐实现伪代码：

```cpp
class item_artifact_chain_weapon : public ItemScript
{
public:
    item_artifact_chain_weapon() : ItemScript("item_artifact_chain_weapon") {}

    bool OnCastItemCombatSpell(Player* player, Unit* victim, SpellInfo const* spellInfo, Item* item) override
    {
        if (!player || !victim || !spellInfo || !item)
            return true;

        int32 damagePct = spellInfo->Effects[EFFECT_0].CalcValue(); // [81] 主伤害比例，万分比
        int32 miscValue = spellInfo->Effects[EFFECT_1].CalcValue(); // [82] 副效果参数
        int32 marker    = spellInfo->Effects[EFFECT_2].CalcValue(); // [83] 神器标记

        if (marker < 9100101 || marker > 9100105)
            return true; // 非神器技能，让官方逻辑继续 CastSpell

        uint64 artifactPower = CalculateArtifactPower(player);
        uint64 damage = artifactPower * uint64(damagePct) / 10000;

        switch (marker)
        {
            case 9100101: // 天雷裁决
                DealArtifactDamage(player, victim, damage, SPELL_SCHOOL_MASK_NATURE);
                break;
            case 9100102: // 万剑归宗
                DealArtifactDamage(player, victim, damage, SPELL_SCHOOL_MASK_NORMAL);
                break;
            case 9100103: // 时空禁锢
                DealArtifactDamage(player, victim, damage, SPELL_SCHOOL_MASK_ARCANE);
                TryRoot(victim, miscValue);
                break;
            case 9100104: // 噬魂回响
                DealArtifactDamage(player, victim, damage, SPELL_SCHOOL_MASK_SHADOW);
                HealCasterByDamagePct(player, damage, miscValue);
                break;
            case 9100105: // 终焉星爆
                DealArtifactDamage(player, victim, damage, SPELL_SCHOOL_MASK_ARCANE);
                break;
        }

        return true; // 保留官方 CastSpell，用于播放 Spell.dbc 视觉和客户端表现
    }
};
```

返回值规则：

- `return true`：允许官方继续 `CastSpell`，适合保留 DBC 视觉、音效、飞行弹道和客户端战斗表现。
- `return false`：阻止官方 `CastSpell`，适合脚本完全接管效果时使用。本项目默认不使用，避免视觉不播放。

这种方式下，后续技能 ID 从 `381001..381080` 改成任意其他 ID，只需要同步修改：

- `Spell.dbc` 中那行技能的 ID。
- `item_template.spellid_1..5` 中引用的新技能 ID。

不需要修改：

- C++ 技能类型判断。
- C++ 伤害比例。
- `spell_script_names` 逐 ID 绑定。

因为脚本看的是 DBC 行里的 `EffectBasePoints_3` 标记，而不是技能 ID。

后续实现模块脚本时，建议新建或扩展神器任务链模块源码，例如：

- `modules\神器任务链\src\ArtifactQuestChain.cpp`
- 注册 `item_artifact_chain_weapon`
- 如需确认脚本加载，可使用 `LOG_INFO("server.loading", "...")` 输出到 `worldserver` 控制台

## 实现顺序

1. 创建 world SQL，写入物品、材料、任务、NPC、Boss、掉落表数据。
2. 使用 `az database import world <sql文件> --confirm` 导入 SQL。
3. 编写或扩展 DBC 生成脚本，创建 `381001..381080` 技能，DBC 写触发壳、视觉壳、说明文本和 `EffectBasePoints_1..3` 比例参数。
4. 优先验证 DBC 原生效果是否能完成技能触发、伤害、吸血和控制。
5. 若 DBC 原生效果无法完成“按神器战力百分比伤害”，再编写 `ItemScript::OnCastItemCombatSpell` 增强脚本，脚本读取 DBC 标记，不绑定固定技能 ID。
6. 将生成后的 `Spell.dbc` 同步到服务端 DBC，并打包客户端补丁。
7. 游戏内验证任务链、材料掉落、神器升级、装备属性、技能显示和击中触发伤害。

## 验证清单

- `item_template` 中存在 `90001..90016` 神器与 `90017..90032` 材料。
- 每把神器 `StatsCount=10`。
- 每把神器 `stat_type1..10` 顺序与本文档一致。
- `quest_template` 中存在 `30001..30016`。
- 每个任务都要求对应材料 x100。
- 第 2 到第 16 阶任务额外要求上一阶神器 x1。
- `creature_template` 中存在 `91001..91017`。
- `creature_queststarter` 和 `creature_questender` 都绑定 `91001` 与全部 16 个任务。
- `creature_loot_template` 中 `91002..91017` 每个 Boss 都掉落对应材料，且 `MinCount=1`、`MaxCount=1`、`Chance=100`、`QuestRequired=1`。
- `Spell.dbc` 中存在 `381001..381080`。
- 每把神器装备模板绑定正确的 5 个技能 ID。
- 每把神器 `spelltrigger_1..spelltrigger_5` 全部为 `2`，第5个终焉星爆也是击中触发。
- DBC 的 `EffectBasePoints_1` 写万分比伤害比例，不写千万、亿、十亿级固定伤害。
- DBC 的 `EffectBasePoints_2` 写副效果参数：时空禁锢定身秒数、噬魂回响治疗万分比。
- DBC 的 `EffectBasePoints_3` 写神器专属标记：`9100101..9100105`。
- 技能生效不依赖 `spell_script_names` 逐 ID 绑定；改技能 ID 后，只要 DBC 行完整且装备模板引用新 ID，技能仍应能触发。
- 如实现 `ItemScript::OnCastItemCombatSpell` 增强脚本，脚本不使用 `spellId - 381001`，不按 ID 范围判断技能类型，只读取 `EffectBasePoints_1..3`。
- 随机抽一个技能 ID 改到非连续 ID 后验证：更新 DBC 行 ID 和 `item_template.spellid_*` 后，技能仍能触发并按 DBC 参数生效。
- 终焉星爆不能作为主动技能点击释放，只能在击中时按 PPM 和冷却触发。

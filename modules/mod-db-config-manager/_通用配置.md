# 通用配置管理

`mod-db-config-manager` 用于把模块配置从本地 `configs/modules` 迁移到 World 数据库表 `通用配置`。

服务器启动时不再读取 `build/bin/RelWithDebInfo/configs/modules` 下的模块配置文件，而是在 World 数据库连接成功后读取 `通用配置` 表，并把配置键值注入到 `sConfigMgr`。模块代码中原有的 `sConfigMgr->GetOption("配置键", 默认值)` 不需要逐个改。

当前只保留一张表：`通用配置`。每行代表一个模块配置项，后台按 `模块名称` 分组管理。

## 文件位置

- 表结构与默认数据：`modules/mod-db-config-manager/sql/world/_通用配置.sql`
- 模块源码：`modules/mod-db-config-manager/src/`
- 早期加载入口：`src/server/apps/worldserver/Main.cpp`
- 通用配置注入接口：`src/common/Configuration/Config.h`、`src/common/Configuration/Config.cpp`

## 表结构

表名：`通用配置`

| 字段 | 说明 |
| --- | --- |
| `配置ID` | 配置项ID |
| `模块ID` | 模块编号，同一模块的配置使用相同模块ID |
| `模块名称` | 中文模块名称，例如 `突破系统`、`物品回收` |
| `模块标识` | 模块内部标识或来源，例如原 conf 文件名 |
| `配置键` | 程序读取用的原始配置键，必须和代码里的 `sConfigMgr->GetOption(...)` 完全一致 |
| `配置名称` | 中文显示名称，方便后台管理 |
| `配置值` | 配置值；`NULL` 表示不覆盖代码默认值，空字符串会作为有效配置值加载 |
| `配置说明` | 中文配置用途说明 |
| `启用状态` | `1` 表示加载此配置，`0` 表示忽略此配置 |

## 导入

把 SQL 导入 World 数据库：

```sql
SOURCE modules/mod-db-config-manager/sql/world/_通用配置.sql;
```

如果使用图形化数据库工具，直接执行 `_通用配置.sql` 内容即可。

## 修改配置

修改配置值：

```sql
UPDATE `通用配置`
SET `配置值` = '0'
WHERE `模块名称` = '物品回收'
  AND `配置键` = 'ItemRecycle.Enable';
```

禁用某个模块的所有配置：

```sql
UPDATE `通用配置`
SET `启用状态` = 0
WHERE `模块名称` = '物品回收';
```

让某个配置项不覆盖代码默认值：

```sql
UPDATE `通用配置`
SET `配置值` = NULL
WHERE `配置键` = 'ItemRecycle.Enable';
```

需要配置为空字符串时，不要设为 `NULL`。例如 Eluna 的 require 路径可以保存为空字符串，表示不追加额外路径。

新增配置项：

```sql
INSERT INTO `通用配置` (`模块ID`, `模块名称`, `模块标识`, `配置键`, `配置名称`, `配置值`, `配置说明`, `启用状态`)
VALUES (999, '示例模块', 'example-module', 'ExampleModule.Enable', '是否启用', '1', '是否启用示例模块', 1)
ON DUPLICATE KEY UPDATE
  `配置名称` = VALUES(`配置名称`),
  `配置值` = VALUES(`配置值`),
  `配置说明` = VALUES(`配置说明`),
  `启用状态` = VALUES(`启用状态`);
```

## 热重载

修改数据库后，在 worldserver 控制台或 GM 命令中执行：

```text
.reload config
```

该命令会重新读取 `通用配置` 表。

注意：热重载是否马上影响模块行为，取决于模块代码是否在运行中重新读取配置，或是否实现了 `OnAfterConfigLoad`。如果某个模块只在启动时缓存配置值，则需要重启服务器或给该模块补充重载逻辑。

## 启用和关闭模块

数据库不能卸载已经编译进 worldserver 的 C++ 模块，只能控制模块自己的启用开关和配置值。

多数模块使用类似下面的开关：

- `xxx.Enable`
- `xxx.Enabled`
- `xxx.Debug`

如果某个模块没有启用开关，需要在模块代码中新增一个 `sConfigMgr->GetOption<bool>("模块名.Enable", true)` 判断，才能通过 `通用配置` 表控制它。

## 维护规则

- 只保留一张 `通用配置` 表，不再创建 `通用配置_*` 分表。
- 新增模块配置时，优先在 `通用配置` 中新增一行。
- 不再依赖 `build/bin/RelWithDebInfo/configs/modules` 作为模块配置来源。
- `配置键` 必须和代码里的 `sConfigMgr->GetOption(...)` 名称完全一致，不能为了中文显示而改名。
- 后台界面按 `模块名称` 分组展示，主要编辑 `配置名称`、`配置值`、`配置说明`、`启用状态`。

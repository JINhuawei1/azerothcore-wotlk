# 自定义UI称号系统

## 描述

这个模块实现了一个基于需求系统的称号激活功能。

玩家不能自动获得称号，必须手动执行命令激活。激活成功后，数据会写入角色库。玩家每次登录时，模块会从角色库加载已激活称号，并且只给玩家应用“最高称号等级”对应的光环技能。

## 功能

- 使用 world 表 `自定义ui_称号系统` 配置称号数据
- `需求系统id` 关联 `mod-requirement-template` 的 `_模板_需求.id`
- 玩家手动激活称号时，先检查需求，再消耗需求
- 激活成功后写入 characters 表 `_玩家称号系统`
- 玩家登录时从角色库恢复已激活称号数据
- 同一角色只生效一个称号光环，始终取已激活称号中的最高等级
- 服务器完全启动后延迟 3 秒初始化模块
- 启动时输出日志 `→自定义UI称号系统√`

## 数据库结构

### world 表：自定义ui_称号系统

SQL 文件：
`modules/mod-zdyui_chenghao/data/sql/wodrid/_自定义ui_称号系统.sql`

| 字段名 | 说明 |
|--------|------|
| id | 称号唯一ID |
| 称号等级 | 用于比较高低，玩家只会生效最高等级的称号光环 |
| 需求系统id | 关联 `mod-requirement-template` 的 `_模板_需求.id` |
| 激活光环技能id | 激活后写入角色数据，登录时加载到玩家 |
| 称号描述 | 游戏内和插件中使用的描述文本 |

### characters 表：_玩家称号系统

SQL 文件：
`modules/mod-zdyui_chenghao/data/sql/characters/_玩家称号系统.sql`

| 字段名 | 说明 |
|--------|------|
| 玩家GUID | 玩家角色GUID |
| 称号ID | 对应 world 表 `自定义ui_称号系统.id` |
| 称号等级 | 激活时保存的称号等级 |
| 光环技能id | 登录时重新加载的光环技能 |

## 激活规则

1. 玩家执行手动激活命令
2. 模块根据 `称号ID` 读取 world 表配置
3. 使用 `需求系统id` 调用需求系统检查条件
4. 条件满足后调用需求系统扣除需求
5. 激活成功后把称号数据写入 `_玩家称号系统`
6. 模块立即重新计算当前最高等级称号，并只给玩家应用该称号的光环

## 登录加载规则

1. 玩家登录时从 `_玩家称号系统` 读取所有已激活称号
2. 移除本模块管理的旧光环
3. 只保留并应用“最高称号等级”对应的一个光环技能

如果多个称号等级相同，则优先使用 `id` 更小的称号。

## 命令

- `.称号 重载`
重新加载 world 表称号配置。

- `.称号 激活 <称号ID>`
激活指定称号。

- `.称号 激活 全部`
检查当前全部称号配置，满足需求的全部激活。

- `.称号 刷新`
从角色库重新读取已激活称号，并重新应用当前最高等级光环。

- `.称号 列表`
显示全部称号配置，并标记：
`当前生效` / `已激活` / `未激活`

## 配置

配置文件：
`modules/mod-zdyui_chenghao/conf/mod_zdyui_chenghao.conf.dist`

当前配置项：

- `ZDYUI.ChengHao.Enable`
是否启用模块。

- `ZDYUI.ChengHao.NotifyPlayer`
称号激活和刷新时是否给玩家发送提示。

## 启动流程

- 服务器启动后，模块不会立即加载数据
- 等待 3 秒后输出启动日志
- 然后执行称号数据初始化

## 注意事项

- 本模块依赖 `mod-requirement-template`
- 如果需求系统未加载，称号无法激活
- 本模块不会自动激活称号，只支持玩家手动激活
- 玩家最终只会生效一个称号光环，不会同时生效多个称号光环

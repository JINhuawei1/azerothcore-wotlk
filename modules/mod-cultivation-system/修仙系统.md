## 二、核心设计理念 — 消耗走需求系统

### 什么是需求系统？
`mod-requirement-template` 是一个通用的需求检查与消耗框架。修仙系统**不自己处理任何材料消耗**，而是给每个等级配置一个`需求系统ID`，调用需求系统来完成：

```cpp
// 检查玩家是否满足升级条件（灵石、物品、等级等）
bool canUpgrade = sRequirementSystem->CheckRequirements(player, 需求ID, true);

// 扣除所有消耗（灵石、物品、金币等由需求系统自动处理）
bool consumed = sRequirementSystem->ConsumeRequirements(player, 需求ID);
```

### 好处
- 修仙系统代码无需关心"扣什么、扣多少"
- 所有消耗通过SQL配置 `_模板_需求` 表即可调整
- 可以灵活组合：灵石+金币+物品+等级要求等任意条件
- 与服务器其他系统（货币、VIP等）天然打通

## 三、数据库设计

### 3.1 世界库表

#### `_修仙境界配置` — 境界与属性加成

| 字段 | 类型 | 说明 |
|------|------|------|
| 境界等级 | INT | 1-100，主键 |
| 境界名称 | VARCHAR(50) | 如"炼气期一重" |
| 大境界 | TINYINT | 1-10，对应十大境界 |
| 小境界 | TINYINT | 1-10，大境界内的小等级 |
| 属性加成百分比 | FLOAT | 全属性加成百分比 |
| 升级需求ID | INT | 关联 `_模板_需求.id`，升到此级的消耗条件 |
| 是否需要渡劫 | TINYINT | 0=否 1=是（仅大境界第10级） |
| 渡劫需求ID | INT | 渡劫额外消耗条件（需求系统ID），0=无额外消耗 |
| 渡劫Boss入口 | INT | 渡劫Boss的 creature_template.entry |

```sql
DROP TABLE IF EXISTS `_修仙境界配置`;
CREATE TABLE `_修仙境界配置` (
  `境界等级` int unsigned NOT NULL COMMENT '1-100',
  `境界名称` varchar(50) NOT NULL DEFAULT '',
  `大境界` tinyint unsigned NOT NULL COMMENT '1-10',
  `小境界` tinyint unsigned NOT NULL COMMENT '1-10',
  `属性加成百分比` float NOT NULL DEFAULT '0' COMMENT '全属性加成%',
  `升级需求ID` int unsigned NOT NULL DEFAULT '0' COMMENT '关联_模板_需求.id',
  `是否需要渡劫` tinyint unsigned NOT NULL DEFAULT '0',
  `渡劫需求ID` int unsigned NOT NULL DEFAULT '0' COMMENT '渡劫额外消耗，关联_模板_需求.id',
  `渡劫Boss入口` int unsigned NOT NULL DEFAULT '0' COMMENT 'creature_template.entry',
  PRIMARY KEY (`境界等级`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='修仙境界配置表';
```

### 6.3 升级核心逻辑（伪代码）

```cpp
bool CultivationMgr::TryUpgrade(Player* player)
{
    auto* data = GetPlayerData(player);
    if (!data) return false;

    uint32 nextLevel = data->level + 1;
    if (nextLevel > 100) return false; // 已满级

    auto it = _realmConfigs.find(nextLevel);
    if (it == _realmConfigs.end()) return false;

    const auto& config = it->second;

    // 如果需要渡劫，走渡劫流程而不是直接升级
    if (config.needTribulation)
    {
        ChatHandler(player->GetSession()).SendSysMessage("需要渡劫才能突破此境界！");
        return false;
    }

    // 通过需求系统检查消耗条件
    if (config.upgradeRequireId > 0)
    {
        if (!sRequirementSystem->CheckRequirements(player, config.upgradeRequireId, true))
            return false;

        // 扣除消耗
        if (!sRequirementSystem->ConsumeRequirements(player, config.upgradeRequireId))
            return false;
    }

    // 升级成功
    data->level = nextLevel;
    SavePlayerData(player);

    // 刷新属性加成
    RemoveStatBonus(player);
    ApplyStatBonus(player);

    // 检查是否解锁新技能
    LearnAvailableSkills(player);

    // 通知玩家
    ChatHandler(player->GetSession()).PSendSysMessage(
        "修炼突破！当前境界: %s，属性加成: %.1f%%",
        config.name.c_str(), config.statBonus);

    return true;
}
```

### 6.4 渡劫核心逻辑（伪代码）

```cpp
bool CultivationMgr::StartTribulation(Player* player)
{
    auto* data = GetPlayerData(player);
    if (!data) return false;

    uint32 nextLevel = data->level + 1;
    auto it = _realmConfigs.find(nextLevel);
    if (it == _realmConfigs.end()) return false;

    const auto& config = it->second;

    // 必须是需要渡劫的等级
    if (!config.needTribulation)
    {
        ChatHandler(player->GetSession()).SendSysMessage("当前境界无需渡劫。");
        return false;
    }

    // 检查冷却
    if (data->tribCooldown > time(nullptr))
    {
        uint32 remaining = data->tribCooldown - time(nullptr);
        ChatHandler(player->GetSession()).PSendSysMessage(
            "渡劫冷却中，还需等待 %u 分钟", remaining / 60 + 1);
        return false;
    }

    // 通过需求系统检查渡劫消耗
    if (config.tribRequireId > 0)
    {
        if (!sRequirementSystem->CheckRequirements(player, config.tribRequireId, true))
            return false;

        if (!sRequirementSystem->ConsumeRequirements(player, config.tribRequireId))
            return false;
    }

    // 召唤渡劫Boss
    float x, y, z, o;
    player->GetPosition(x, y, z, o);
    Creature* boss = player->SummonCreature(config.tribBossEntry, x + 5, y, z, o,
                                             TEMPSUMMON_TIMED_OR_DEAD_DESPAWN, 300000);
    if (boss)
    {
        boss->SetInCombatWith(player);
        boss->AI()->AttackStart(player);
        // 标记Boss属于此玩家的渡劫
    }

    return true;
}
```

## 八、渡劫系统流程

```
渡劫流程:
1. 玩家通过NPC或命令发起渡劫
2. 检查条件:
   a. 当前等级是大境界的第10级（如10、20、30...）
   b. 渡劫冷却已过
   c. 需求系统检查通过（sRequirementSystem->CheckRequirements）
3. 需求系统扣除消耗（sRequirementSystem->ConsumeRequirements）
4. 在玩家位置召唤渡劫Boss
5. 玩家击杀Boss → 渡劫成功 → 等级+1进入下一大境界 → 解锁新仙术
6. 玩家被Boss击杀 → 渡劫失败 → 进入冷却（10分钟）
7. Boss在战斗中不可被其他玩家协助（私人渡劫）
```

## 十、灵石设计

灵石作为**游戏物品**存在于玩家背包中，不再是修仙系统内部的虚拟货币：

- 在 `item_template` 中创建灵石物品
- 怪物掉落通过 `creature_loot_template` 配置
- 需求系统通过 `消耗物品` 字段检查和扣除灵石
- 这样灵石可以交易、邮寄、拍卖，增加经济互动
